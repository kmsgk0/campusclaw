## Context

现有系统以 SQLite 持久化材料和身份，使用 JWT Bearer 登录。材料上传的保存事务及班级隔离保持不变；外部向量和模型服务失败不能伪装成无匹配。

## Decisions

切片保留上传正文中的原始字符下标，范围采用左闭右开，切片编号从 0 开始。优先在段落、换行、句号处断开，无断点则按 800 字切分，最多重叠 80 字。所有切片完整保存。

SQLite FTS5 输入中文相邻二元词和英文词，排除常见问句词后以 BM25 排序；Qdrant 使用余弦距离并只在内部网络开放。两条检索路径均限定身份班级，向量结果回表再次检查班级和索引就绪状态。混合检索先过滤再以 RRF k=60 融合。检索结果分页，问答明确取前 4 条。

材料与正文先按原事务保存，再执行外部索引。每份材料记录 pending/ready/failed 和明确错误；只有 ready 材料参加检索。失败时保留原材料，上传响应说明索引未完成；教师可显式重试本班材料。索引操作以进程锁避免单实例内重复计费。缺失索引通过 CLI 补齐，启动不调用付费 API。

为避免重复嵌入，相同班级的切片内容按服务地址、模型、维度和文本哈希缓存向量；成功的每次嵌入立即持久化。该缓存是对外部付费计算结果的复用，便于索引失败后重试和重复上传。Qdrant 主键对应切片 id。切分和索引本身幂等，重启不重算；模型配置变更需显式重建。

问答只使用本次问题，服务端组装带编号的授权切片，材料中的指令作为不可信正文。无命中直接返回固定文案及空引用。存在候选但模型确认依据不足时，也返回固定文案及空引用。回答限简短中文，输出预算 512 token；服务端核对引用编号属于提供的切片。超时、配额耗尽、格式错误和无效引用明确报错，不自动重试、不切换服务，也不返回编造的答案。日志只记录用途和接口提供的 token 计数，不记录问题、正文、密钥。

界面沿用现有材料工作台，新增知识检索和知识问答入口。搜索结果、问题、答案与来源完整可读，打开来源通过鉴权取得原文并突出切片范围。独立保存输入、检索结果、问答结果及错误；请求未完成时禁止重复提交。

## Verification

真实 SQLite、Qdrant 本地模式和模拟网关覆盖切片、分页、权限、引用、重启及失败恢复；真实网关仅用于必要的索引与少量端到端场景。在部署环境通过浏览器验证问答和来源，复用已有答案检查不同屏幕宽度。
